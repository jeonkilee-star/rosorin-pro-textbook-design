1학습목표
  • 배터리를 안전하게 연결하고 규정된 순서로 충전할 수 있다.
  • 정상 부팅 여부를 LED·부저(buzzer) 신호로 판별할 수 있다.
  • 부팅 이상 발생 시 SD카드 접촉 불량 등 기본 원인을 진단하고 조치할 수 있다.
2필요지식
  • 리튬 배터리는 운송 규정상 완충 상태로 출고되지 않으므로 최초 사용 전 충전이 필수다.
  • 배터리 극성(적/흑)을 반대로 연결하면 회로 손상 위험이 있다.
  • 충전기는 배터리 DC 포트 전용이며, Jetson 메인보드 DC 입력에 연결하면 보드가 손상된다.

안전·유의사항
  1. 전원 스위치가 꺼진 상태에서만 배터리 커넥터를 연결한다.
  2. 적-적, 흑-흑 극성(polarity)을 확인한다. 역결선 금지.
  3. 충전기는 반드시 배터리 DC 포트에 연결한다 — Jetson 보드 DC 입력 절대 금지.
  4. 배터리 전압이 10V 미만이면 부저 경고음이 울린다. 즉시 충전한다.

전원, 충전, 초기 부팅

리튬 배터리는 완충 상태로 오지 않습니다. 순서를 지켜야 보드 손상 없이 첫 부팅을 마칠 수 있습니다.

이 레슨이 끝나면

  • 배터리를 안전하게 연결하고 순서대로 충전할 수 있다
  • LED·부저(buzzer) 신호로 정상 부팅 여부를 판별할 수 있다
  • 부팅이 안 될 때 SD카드 접촉 불량을 스스로 진단·조치할 수 있다

준비물

M4×6 나사 ×4 (로봇팔)M3×6 나사 ×4 (카메라 브라켓)내육각 렌치정품 충전기조립 매뉴얼 2·7p

⚠ 안전 유의사항

  • 전원 스위치 OFF 상태에서만 배터리 커넥터 연결
  • 적-적 / 흑-흑 극성(polarity) 확인 — 역결선 절대 금지
  • 충전기는 배터리 DC 포트 전용 — Jetson 보드 DC 입력 금지(보드 손상)
  • 전압 10V 미만 시 부저 경고음 — 즉시 충전

전원 ON 후 약 1분 대기. LED1 파란 점멸 + 부저 1회면 정상입니다.

1학습목표
  • ROS2 작업환경을 활성화하고 현재 실행 중인 노드·토픽 목록을 확인할 수 있다.
  • 최소 구성의 rclpy 노드를 작성하고 실행할 수 있다.
  • 실행 로그와 ros2 node list로 노드의 정상 동작 여부를 확인할 수 있다.
2필요지식
  • ROS2 프로그램은 노드(Node) 단위로 실행되며, 노드는 토픽(Topic)을 통해 메시지를 주고받는다.
  • 이 로봇의 ROS2 배포판은 Humble, 작업공간은 ~/ros2_ws이며 로그인 쉘이 zsh다.
  • 작업환경을 불러오지 않으면 ros2 명령 자체가 인식되지 않는다.
3수행내용

기기(장비·공구)SSH 접속 가능한 PC, ROSOrin Pro 로봇, 터미널 2개
안전·유의사항
  1. 새 터미널을 열 때마다 source /opt/ros/humble/setup.zsh; source ~/ros2_ws/install/setup.zsh를 반드시 실행한다.
  2. 노드 이름은 로봇에서 이미 실행 중인 시스템 노드와 겹치지 않게 짓는다.

  • 새로 실행한 퍼블리셔에서 --once(1회성) 발행은 구독자와 매칭되기 전에 유실될 수 있음이 실측으로 확인됐다(정지·그리퍼(gripper) 명령 모두 재현). 반드시 반복 발행 방식을 쓴다.

#!/usr/bin/env python3 import time, rclpy from rclpy.node import Node from geometry_msgs.msg import Twist class FirstMove(Node): def __init__(self): super().__init__('first_move') self.pub = self.create_publisher(Twist, '/controller/cmd_vel', 1) def move_forward(self, seconds=5.0, speed=0.2): twist = Twist(); twist.linear.x = speed end = time.time() + seconds while time.time() < end: self.pub.publish(twist) # 반복 발행 — --once 유실 방지 time.sleep(0.1) self.pub.publish(Twist()) # 정지도 발행으로 def main(): rclpy.init() FirstMove().move_forward() rclpy.shutdown() if __name__ == '__main__': main()

09-1. 로봇팔 첫 동작 — 서보(servo) 각도로 관절(joint) 움직이기

훈련시간1.5시간 (실습 + 결과기록 포함)
선수 학습03. 이동 제어

서보 ID ↔ 관절 대응(Hiwonder 공식 매뉴얼 8장 기준) — ID1 베이스 회전(팬) · ID2 어깨(shoulder) · ID3 팔꿈치(elbow) · ID4·ID5 손목(wrist) · ID10 그리퍼(gripper). 오늘은 이 중 ID3(팔꿈치)를 움직여봅니다.

1학습목표
  • 사진에 표시된 서보 ID(1, 2, 3, 4, 5, 10)와 실제 관절 부위를 정확히 대응시켜 설명할 수 있다.
  • 서보 ID·목표값(0~1000)·지속시간을 지정해 로봇팔 관절을 안전하게 움직일 수 있다.
  • 실행 전 예측과 실제 결과를 비교하고, 그 차이의 이유를 논리적으로 서술할 수 있다.
2필요지식
  • 로봇팔은 지능형 버스 서보 6개로 구성된다 — ID1 베이스 회전(팬), ID2·3·4 팔 관절, ID5 손목, ID10 그리퍼. (Hiwonder 공식 매뉴얼 8장)
  • 서보 위치값은 0~1000 범위이며, 중앙값(약 500)이 정자세에 해당한다. 실제 각도가 아닌 이 정수값으로 목표를 지정한다.
  • 서보 명령은 /servo_controller 토픽(ServosPosition 메시지)으로 발행하며, 공식 헬퍼 함수 set_servo_position(pub, duration, ((id, position), ...))(servo_controller.bus_servo_control)를 사용하는 것이 권장 방식이다.

재료·자료없음 (소프트웨어 실습)
기기(장비·공구)ROSOrin Pro, 로봇팔 주변 30cm 이상 여유공간
안전·유의사항
  1. 로봇팔이 움직이는 동안 관절 사이에 손가락을 넣지 않는다.
  2. 최초 테스트는 중앙값(500) 근처 ±30 이내(약 ±7도)의 작은 변화로 시작한다.
  3. 그리퍼(서보 ID 10) 최초 테스트는 빈손으로만 진행한다 — 손가락 협착 위험.
  4. 이상 동작 시 즉시 전원 스위치로 강제 정지한다.

로봇팔 첫 동작 — 서보(servo)로 관절(joint) 움직이기

서보 ID와 각도를 지정해 관절을 움직이고, 실행 전 예측과 실제 결과를 비교하며 기록으로 남깁니다.

서보 ID ↔ 관절 대응(Hiwonder 공식 매뉴얼 8장 기준) — ID1 베이스 회전(팬) · ID2 어깨(shoulder) · ID3 팔꿈치(elbow) · ID4·ID5 손목(wrist) · ID10 그리퍼(gripper). 오늘은 이 중 ID3(팔꿈치)를 움직여봅니다.

이 레슨이 끝나면

  • 사진 속 서보 ID(1,2,3,4,5,10)와 실제 관절 부위를 정확히 대응시킬 수 있다
  • 서보 ID·목표값(0~1000)·지속시간으로 관절을 안전하게 움직일 수 있다
  • 실행 전 예측과 실제 결과를 비교하고 이유를 서술할 수 있다

03-2. 바퀴 전방향 테스트 — 전진(forward)·평행이동(lateral translation)·회전(rotation) 모두 확인하기

학습모듈명ROSOrin Pro 활용 자율주행 로봇 프로그래밍
훈련시간1시간 (실습 + 결과기록 포함)
선수 학습03-1. 첫 이동 명령

메카넘 휠(mecanum wheel) 4개(A·B·C·D) 기구학(kinematics) 다이어그램(Hiwonder 공식 매뉴얼 2.2절 기준) — 바퀴 롤러가 45도로 붙어있어, 네 바퀴 회전을 조합하면 전진/후진(backward)뿐 아니라 옆으로 평행이동·제자리 회전까지 가능합니다. 오늘은 이 조합을 6가지 이동(전진·후진·좌우 평행이동·좌우회전(turn right, CW))으로 나눠 하나씩 테스트합니다.

1학습목표
  • Twist 메시지의 linear.x·linear.y·angular.z를 조합해 로봇을 여러 방향으로 움직일 수 있다.
  • 각 축의 부호(+/-)가 실제로 어느 방향에 대응하는지 직접 실험으로 확인하고 기록할 수 있다.
  • 전진·후진·좌우 평행이동·좌우회전 6가지 이동을 모두 시도하고 결과를 기록으로 남길 수 있다.
2필요지식
  • ROSOrin Pro는 메카넘 휠 구동이라 일반 바퀴와 달리 옆으로 평행이동도 가능하다 — 바퀴 롤러가 45도로 붙어있어 네 바퀴 조합으로 이런 움직임이 나온다. (Hiwonder 공식 매뉴얼 2.2절)
  • /controller/cmd_vel 토픽(geometry_msgs/Twist)의 linear.x(전후진)·linear.y(좌우 평행이동)·angular.z(회전)를 조합해 발행한다.
  • 확인된 값: linear.x 권장 범위 −0.6~0.6 m/s, angular.z는 양수면 좌회전(반시계) 음수면 우회전(시계방향)이다. (공식 매뉴얼 2.1.5절)
  • linear.y의 부호가 실제로 좌/우 중 어느 쪽인지는 공식 문서에 명시돼 있지 않다 — 이번 실습에서 직접 테스트하고 기록하는 것 자체가 학습 목표다.
  • 03-1에서 배운 반복 발행(repeated publish) 원칙(--once 유실 방지)이 여기에도 동일하게 적용된다.
3수행내용
재료·자료없음 (소프트웨어 실습)
기기(장비·공구)ROSOrin Pro, 전후좌우 대각선 포함 1.5m 이상 여유공간
안전·유의사항
  1. 실습 전 로봇 전후좌우(대각선 포함) 1.5m 이상 공간을 확보한다.
  2. 모든 테스트는 저속(0.2 m/s 이하)으로 시작한다.
  3. 정지 명령도 1회성이 아닌 반복 발행으로 보낸다.
  4. 대각선 이동(전진+평행이동 동시)은 더 넓은 공간에서 마지막에 시도한다.
순번절차판정기준
1전진(linear.x=+0.2) → 후진(linear.x=−0.2) 테스트앞/뒤로 직진 이동
2linear.y=+0.2로 평행이동 테스트 → 실제 방향(좌/우) 관찰옆으로 이동, 방향 기록
3linear.y=−0.2로 반대 방향 평행이동 테스트반대쪽으로 이동 확인
4angular.z=+0.3(좌회전(turn left, CCW)) → −0.3(우회전) 테스트제자리에서 회전
5linear.x+linear.y 동시 입력으로 대각선 이동 테스트대각선 방향으로 이동

#!/usr/bin/env python3 import time import rclpy from rclpy.node import Node from geometry_msgs.msg import Twist class WheelTest(Node): def __init__(self): super().__init__('wheel_test') self.pub = self.create_publisher(Twist, '/controller/cmd_vel', 1) def move(self, vx=0.0, vy=0.0, wz=0.0, seconds=2.0): twist = Twist() twist.linear.x = vx twist.linear.y = vy twist.angular.z = wz end = time.time() + seconds while time.time() < end: self.pub.publish(twist) # 반복 발행 — --once 유실 방지 time.sleep(0.1) self.pub.publish(Twist()) # 정지도 발행으로 def main(): rclpy.init() node = WheelTest() node.move(vx=0.2, seconds=2.0) # 1. 전진 time.sleep(1.0) node.move(vy=0.2, seconds=2.0) # 2. 평행이동(방향은 관찰해서 기록) time.sleep(1.0) node.move(wz=0.3, seconds=2.0) # 4. 회전 rclpy.shutdown() if __name__ == '__main__': main()

바퀴 롤러가 45도로 붙어있어서(위 다이어그램), 네 바퀴를 다른 속도로 돌리면 옆으로도 미끄러지듯 움직입니다. 일반 바퀴는 못 하는 거예요.

2

코드 하나로 다 테스트

move(vx, vy, wz) 함수 하나만 만들어두고 값만 바꿔가며 부릅니다.

import time, rclpy from rclpy.node import Node from geometry_msgs.msg import Twist class WheelTest(Node): def __init__(self): super().__init__('wheel_test') self.pub = self.create_publisher(Twist, '/controller/cmd_vel', 1) def move(self, vx=0.0, vy=0.0, wz=0.0, seconds=2.0): t = Twist(); t.linear.x = vx; t.linear.y = vy; t.angular.z = wz end = time.time() + seconds while time.time() < end: self.pub.publish(t) # 반복 발행! time.sleep(0.1) self.pub.publish(Twist()) rclpy.init() node = WheelTest() node.move(vx=0.2, seconds=2.0) # 전진
linear.y 부호는 어느 쪽이 좌/우예요? 공식 문서에도 안 나와 있어서, 직접 돌려보고 아래 표에 적는 게 오늘 과제 중 하나입니다.
3

회전은 부호로 방향이 갈립니다

angular.z가 양수(+)면 좌회전(turn left, CCW), 음수(−)면 우회전입니다(공식 매뉴얼 확인됨).

03 · 이동 제어

바퀴 전방향 테스트 — 전진(forward)·평행이동(lateral translation)·회전(rotation)

메카넘 휠(mecanum wheel)이 만들어내는 모든 이동 방향을 하나씩 직접 확인하고 기록합니다.

메카넘 휠 4개(A·B·C·D) 기구학(kinematics) 다이어그램(Hiwonder 공식 매뉴얼 2.2절 기준) — 바퀴 롤러가 45도로 붙어있어, 네 바퀴 회전을 조합하면 전진/후진(backward)뿐 아니라 옆으로 평행이동·제자리 회전까지 가능합니다. 오늘은 이 조합을 6가지 이동(전진·후진·좌우 평행이동·좌우회전(turn right, CW))으로 나눠 하나씩 테스트합니다.

이 레슨이 끝나면

  • linear.x·linear.y·angular.z를 조합해 로봇을 여러 방향으로 움직일 수 있다
  • 각 축 부호가 실제 어느 방향인지 실험으로 확인하고 기록할 수 있다
  • 전진·후진·평행이동·회전·대각선까지 6가지를 모두 시도하고 기록할 수 있다

준비물

사방 1.5m 이상 공간ROSOrin Pro

⚠ 안전 유의사항

  • 실습 전 로봇 전후좌우·대각선 방향 1.5m 이상 공간 확보
  • 모든 테스트는 저속(0.2m/s 이하)으로 시작
  • 정지 명령도 1회성이 아닌 반복 발행(repeated publish)으로
  • 대각선 이동은 가장 넓은 공간에서 마지막에 시도

수행 순서

1

전진·후진

linear.x를 +0.2, −0.2로 바꿔가며 테스트합니다.

2

평행이동

linear.y를 +0.2, −0.2로 바꿔가며 실제 방향(좌/우)을 관찰합니다.

Tip · 부호-방향 대응은 공식 문서에 없어서 직접 확인해야 합니다
3

회전

angular.z가 +면 좌회전(turn left, CCW), −면 우회전입니다(공식 확인됨).

심화 개념

  • 메카넘 휠(mecanum wheel) 4개는 각각 다른 방향의 대각선 롤러를 가진다 — 네 바퀴를 같은 방향으로 돌리면 전진, 대각선 방향으로 짝을 지어 다르게 돌리면 평행이동(lateral translation)이 나온다. "네 바퀴 회전 속도의 조합"이 곧 로봇의 최종 이동 방향을 결정한다.
  • 대각선 이동은 vx와 vy를 동시에 넣는 것이라 각 바퀴에 걸리는 부하가 순수 전진·평행이동보다 커서, 실제 속도가 이론값보다 느려질 수 있다.
